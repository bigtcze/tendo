# Release qualification

This inventory distinguishes pull-request CI from the release-only qualification gate. The release workflow calls `release-qualification.yml` on the exact tagged SHA, and `verify` waits for that reusable workflow before release publication can proceed. A manual `workflow_dispatch` run is available for exercising qualification against a selected branch/SHA; a branch-only push trigger is enabled on `ci/v2-1-release-qualification` for first proof without publishing.

| Verification layer | Where enforced | Command / workflow | Rationale |
|---|---|---|---|
| Go formatting, vet, maintainability ratchet, unit tests with race, build | Required PR CI (`backend`); full local gate | `gofmt`, `go vet ./...`, `python3 scripts/maintainability_check.py`, `go test -race`, `go build ./...` | Fast source and regression checks on every PR and main push. |
| API generation, OpenAPI/contract, npm audit | Required PR CI (`api`) and full local gate | `cd api && npm ci && npm audit --audit-level=moderate && npm run check` | Generated artifacts and API contract need short feedback. |
| Frontend lint, typecheck, unit, maintainability, audit | Required PR CI (`frontend`) and full local gate | `cd frontend && npm ci && npm audit --audit-level=moderate && npm run check` | Fast frontend regressions/structural checks on every PR. |
| PostgreSQL integration, migrations, sqlc drift, native harness-control and generator tests | Required PR CI (`postgres`) and full local gate | `bash scripts/setup-integration.sh`; `bash scripts/check-sqlc.sh`; the Python test commands in `required.yml` | Real PostgreSQL is part of ordinary PR confidence; native tests preserve no-Docker behavior. |
| Production-built real-PostgreSQL Playwright journey suite (including 1000+ item and collection/history boundary journeys) | Required PR CI (`e2e`) and full local gate | `bash scripts/e2e-smoke.sh` | Core user journeys and scale boundaries are deterministic and suitable for each PR. Uses the native PostgreSQL test-service bootstrap. |
| Runtime, setup, OIDC, proxy (Caddy/Nginx/Traefik), backup/restore, household backup, upgrade, quickstart deployment smokes | Required PR CI (`deployment` matrix) | `timeout "$timeout_seconds" bash "scripts/${SMOKE}.sh"` for each listed matrix entry | Deployment/configuration regressions need actual containerized stacks and are already required, not release-only. |
| Real Orca screen-reader production-browser harness under Xvfb/D-Bus/AT-SPI | Release qualification, plus manual dispatch and qualification-branch push | `TENDO_SR_AUDIT_DIR="$RUNNER_TEMP/tendo-sr-audit" bash scripts/e2e-smoke.sh` (workflow sets the variable and real PostgreSQL service) | Orca/AT-SPI host setup is costly and host-sensitive; this meaningful assistive-technology layer runs on GitHub-hosted Ubuntu as an enforced release prerequisite. Only sanitized `transcript.json`, `transcript.md`, and `manifest.json` are uploaded. Debug output and `runtime/` are never included. |
| Mutation/regression evidence from named V2.1 cases | Required PR CI for mutation harness/control tests; case-specific mutation evidence is recorded in the coverage matrix and maintainability audit; exhaustive candidate mutation execution is currently local/review evidence | Focused injected-regression experiments are recorded by their owning test/audit entries. No broad mutation-testing engine/command is part of `verify-local.sh` or `required.yml`. | The project does not currently provide one deterministic aggregate mutation command. Keep evidence traceable and do not represent ad-hoc mutation experiments as a CI mutation suite. |
| Production published-artifact install/upgrade and multi-architecture image verification | Release workflow after qualification, image publication and GitHub release | `scripts/release-assets.sh`; release workflow's image and release jobs; post-publication install/upgrade checks | Verification against published artifacts cannot be performed on ordinary PRs. It remains an explicit release verification obligation after publication and is not replaced by CI build checks. |

## Qualification runner risk and first proof

The Orca harness has been proven repeatedly only on the local Debian 13 host with Orca 48.1. GitHub-hosted Ubuntu's package versions and Orca behavior may differ; apt package availability, AT-SPI startup and speech behavior are therefore unproven until a successful GitHub run. The workflow records host/package and tool versions in the manifest and has a branch-only push trigger to exercise it before merge. No assertion is made that the Ubuntu job works until such a run succeeds. If branch push dispatch is unavailable, run `workflow_dispatch` on the qualification branch after merge and before tagging; release publication remains blocked until the reusable job succeeds for the exact tag SHA.

The release workflow also verifies the tag points to `main`, checks release notes and the successful `required` check on that commit, rejects existing releases and non-highest tags. Qualification is an additional dependency, not a replacement for any check.
