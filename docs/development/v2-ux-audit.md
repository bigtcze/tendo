metrics are regenerated by the harness and are not committed.

## Dataset

Seeded through the public API only: two members (owner + invited member), 15 subjects (Czech diacritics,
some archived), cumulative stages of 0 / 1 / 30 / 500 / 1200 items from a seeded generator mixing one-off,
fixed and fluid recurrence (day/week/month/year), past/future/no attention dates, historical completion
dates, owner/member/no assignee, ~5 % long titles with long unbreakable Czech words, notes. Lifecycle changes
are applied in generator order, so two consecutive runs produced identical final counts, verified by a full
API page walk: 882 open, 76 in progress, 56 waiting, 57 paused, 69 done, 60 archived (1071 active).

## Decisions

Server-side list contract (oracle): additive, backward-compatible parameters on
`GET /households/{id}/items` — `q` (title + notes, case/diacritic-insensitive literal substring),
`subjectId`, `responsibleUserId` (UUID or `unassigned`), `workflowState`, `attention`
(`needs_attention`/`upcoming`, computed in SQL from household-local today), `recurring`, `sort`
(`created` default, `attention_on` = `attention_on ASC NULLS FIRST, id ASC`) and an optional
`attentionDate` freshness guard. V1 queries keep the `i1` cursor and identical results; extended queries
use a versioned composite cursor bound to household, filter fingerprint and date (mismatch →
400 `invalid_query`). Counts come from a separate `GET …/items/summary` with the same filters, one
aggregate statement, partitioned into needs_attention / in_progress / waiting / upcoming / paused / done /
archived. Search uses `pg_trgm` + `unaccent` (both available in the pinned PostgreSQL 18.6 image) with a
trigger-maintained normalized column and GIN index; the runtime role gets no new DDL or table-write
privileges, only narrowly scoped helper-function EXECUTE if required. Pagination is deterministic keyset
traversal for unchanged rows, not snapshot isolation.

Design direction (designer): keep the warm paper palette and serif display face; add a type and spacing
scale and semantic status text colours (AA-checked against `#faf7f2`, always paired with text labels);
one filled primary action per context; quieter row completion; consistent household navigation on every
route.

## Plan (ordered PR slices)

1. Audit harness + this document (this PR).
2. Backend: structured list filters + extended cursor (no migration), OpenAPI, real-PG tests.
3. Backend: attention sort + date guard + migration 015 indexes.
4. Backend: items summary endpoint (counts).
5. Backend: text search (extensions, normalized column, GIN).
   - PR #112, merged: optional `q` on item list and summary, migration 016 (`unaccent`, `pg_trgm`, trigger-maintained `search_text`, GIN index), fail-closed schema validation.
6. Frontend: server-backed attention-first home with truthful counts and bounded per-group pages; F5, F6, F7.
   - 6a (PR #110, merged): server-backed groups, summary counts in headings, per-group Show more with remaining count, title wrapping — fixes F1 and F5 and the home part of F13.
   - 6b (PR #116, merged): rows show attention date, last done and who looks after the item; row Done is a secondary button so Add item stays the single primary — fixes F6 and F7.
7. Frontend: "All items" search/filter view incl. done and archived, URL-preserved context, bounded rendering (F2–F4, F13).
8. Frontend: shared navigation and design tokens across every route (F8, F10–F12); subject labels without eager loading (F9).
   - 8a (this PR): shared household navigation on every signed-in household route with current-page state (Home and Account only without a household; none on invitations), consistent page headings and width, type-scale tokens, smaller phone heading and padding, no decorative background, and plain setup-code wording — fixes F8, F10, F11 and F12. F9 remains open.
9. Accessibility: automated axe checks in production-build E2E plus keyboard/zoom/reduced-motion review (F14).
   - 9 (this PR): axe-core WCAG 2.0/2.1/2.2 A+AA scans on 18 production-build states (onboarding error, empty and populated home in English and Czech, add/edit forms, item detail, All items with filters and no-match, People and things, Members invite, invitation acceptance, Account, login error, 320 px), keyboard skip-link and sampled visible focus indicator checks (first tab stops in main), 640 px (200 % zoom-equivalent viewport of 1280 px; reflow proxy, not real browser zoom) and 320 px reflow without horizontal overflow, and reduced-motion durations — addresses F14. Automated scans cover only part of WCAG; axe `incomplete` results and passing rule ids are attached per scan; manual screen-reader, real-zoom and full keyboard review are not claimed.
10. Large-dataset production E2E in required CI (1000+ items), docs, release v2.0.0.
   - 10a (this PR): Home caps each group at 100 rows (4 pages of 25); once a group has more, Show more is replaced by a link to All items filtered to that group (with the complete count, or count-free if the summary is stale), which receives focus when Show more had it. The opt-in audit now expects capped expansion (at most 500 Home rows) derived from server counts — closes the remaining unbounded-DOM path on Home (F4).

The audit is re-run after slices 6–8 and the measurements above are replaced, not appended.
