This is the evidence-based starting point required by V2_SCOPE step 1. It records measured problems and the
ordered plan. It is not a specification; each slice is defined and tested in its own PR. Screenshots and
metrics are regenerated by the harness and are not committed.

## Dataset

Seeded through the public API only: two members (owner + invited member), 15 subjects (Czech diacritics,
some archived), cumulative stages of 0 / 1 / 30 / 500 / 1200 items from a seeded generator mixing one-off,
fixed and fluid recurrence (day/week/month/year), past/future/no attention dates, historical completion
dates, owner/member/no assignee, ~5 % long titles with long unbreakable Czech words, notes. Lifecycle changes
are applied in generator order, so two consecutive runs produced identical final counts, verified by a full
API page walk: 882 open, 76 in progress, 56 waiting, 57 paused, 69 done, 60 archived (1071 active).

## Decisions

Server-side list contract (oracle): additive, backward-compatible parameters on
`GET /households/{id}/items` — `q` (title + notes, case/diacritic-insensitive literal substring),
`subjectId`, `responsibleUserId` (UUID or `unassigned`), `workflowState`, `attention`
(`needs_attention`/`upcoming`, computed in SQL from household-local today), `recurring`, `sort`
(`created` default, `attention_on` = `attention_on ASC NULLS FIRST, id ASC`) and an optional
`attentionDate` freshness guard. V1 queries keep the `i1` cursor and identical results; extended queries
use a versioned composite cursor bound to household, filter fingerprint and date (mismatch →
400 `invalid_query`). Counts come from a separate `GET …/items/summary` with the same filters, one
aggregate statement, partitioned into needs_attention / in_progress / waiting / upcoming / paused / done /
archived. Search uses `pg_trgm` + `unaccent` (both available in the pinned PostgreSQL 18.6 image) with a
trigger-maintained normalized column and GIN index; the runtime role gets no new DDL or table-write
privileges, only narrowly scoped helper-function EXECUTE if required. Pagination is deterministic keyset
traversal for unchanged rows, not snapshot isolation.

Design direction (designer): keep the warm paper palette and serif display face; add a type and spacing
scale and semantic status text colours (AA-checked against `#faf7f2`, always paired with text labels);
one filled primary action per context; quieter row completion; consistent household navigation on every
route.

### Measured contrast (2026-10-24)

n21 measures rendered colours on every route it visits (`frontend/e2e/contrastAudit.ts`, maths in
`frontend/e2e/contrast.ts` with Vitest tests) and fails on any shortfall. Measured minimum per rendered pair in
the recorded run:

| Rendered pair (foreground on effective background) | Use | Min ratio | Required |
|---|---|---:|---:|
| ink `#25302b` on paper `#faf7f2` | body text, headings | 12.79:1 | 4.5:1 |
| ink on sand `#efe9df` | selected / hover surfaces | 11.32:1 | 4.5:1 |
| ink on card `rgb(253 253 251)` (white/70 over paper) | rows, forms | 13.42:1 | 4.5:1 |
| muted `#5b655f` on paper | secondary text | 5.66:1 | 4.5:1 |
| muted on card | row metadata | 5.94:1 | 4.5:1 |
| accent-strong `#234f41` on card | links | 9.10:1 | 4.5:1 |
| white on accent `#2f6b57` | primary buttons | 6.25:1 | 4.5:1 |
| field `#857c6e` on paper | form-control borders (1.4.11) | 3.85:1 | 3:1 |
| accent focus outline on paper / card | focus indicator (1.4.11) | 5.85:1 / 6.12:1 | 3:1 |

Finding **A4** (1.4.11): form-control borders used the decorative `line` token (`#d8d0c3`, 1.43:1 on paper,
1.53:1 on white); the white field fill is 1.04:1 against paper, so nothing identified the field edge on login,
invitation acceptance, All items search/filters, add/edit forms, People and things and onboarding. Fix: a
`field` token (`#857c6e`; 3.85:1 on paper, 3.41:1 on sand, 4.11:1 on white) for form-control borders only;
decorative card borders and dividers keep `line`.

Method: text (1.4.3) uses 4.5:1, or 3:1 for large text (≥24 px, or ≥18.66 px at weight ≥700). Foreground
alpha and ancestor opacity are composited over the effective background, which is built from the root outward
over paper. Placeholders are measured against their field. Form controls (1.4.11) must have a border of 3:1
against the surface outside the control unless their own fill differs from it by 3:1. Buttons with a text
label are identified by their text. Native checkboxes, radios and the Repeat/Fluid switches (`accent-color`)
are recorded as native and not measured. Disabled controls are recorded and exempt. A background image fails
as unmeasurable. Every colour is normalized to sRGB through a canvas, because Chromium serializes
`color-mix()` as `oklab()`, and unknown values fail. Measuring waits for entry animations and focus
transitions to finish. Each focus stop of the keyboard sweep compares its outline (or box-shadow) colour with
the composited background around the control (3:1), together with the existing centre hit test (a 2.4.11
proxy). Mutation-checked: `muted` set to `#9aa39d` fails (axe, n14), `field` reverted to `#d8d0c3` fails n21
contrast, and the button focus outline set to `sand` fails n21 focus contrast. Hover states are not
measured. The ring is compared only with the background around the control, not with the control's own fill.
2.4.13 (AAA focus appearance) is not claimed.

### What n21 checks on every route

The routes are Home, All items, People and things, Members, Account, login and invitation acceptance. A route
counts as ready only when its `h1` and a route-specific element (Add item, a result row, a list row, the
preferences heading, the OIDC sign-in button, the join button) are visible (and, on household routes, no loading status remains). n21 checks:

- **ARIA snapshot** of the whole page (`ariaSnapshot()`), printed and attached for an agent to read. The
  snapshots show one `h1` per route; skip link, banner, household navigation, main and footer landmarks; a
  search landmark named "Search items" and a "Results" region in All items (Vitest-asserted); row actions named
  after their item (`Done: …`, `Edit …`, `Archive …`); status regions for notices; a login `alert` region for
  errors; and the language switch as a named group with `pressed` state. Only the `main` landmark is asserted
  in E2E; the rest is reading, not assertion.
- **Keyboard sweep**: Tab from the top of the page to the end. Each stop is tagged with a per-element id. A
  stop passes only if its outline or box shadow differs between focused and blurred (2.4.7), so a permanent
  shadow does not count; its centre must not be covered by another element (a 2.4.11 proxy). Revisiting a
  stop before the footer fails as a loop. The set of reached `main` ids must equal the set of visible, enabled
  controls in `main` (one per radio group), each once; a route other than Account must have at least one.
  The footer language switch must be the last two stops (no trap, 2.1.2). Recorded order: skip link → Sign
  out → navigation → main in reading order → language. Account's `main` has no controls for a password-only
  owner. Mutation-checked: a permanent shadow with focus outline removed, and `tabIndex={-1}` on Members'
  Create invite link, each fail n21.
- **Target size**: every visible interactive element (or the label that wraps it) is at least 24×24 CSS px
  (2.5.8).
- **axe** WCAG 2.0/2.1/2.2 A+AA: no violations. In the recorded run, axe reported no `incomplete` results in
  n14 or n21; any future ones are printed to the process log as `axe-incomplete`. axe passing is not a manual
  contrast review.
- **Zoom** at 200 % and 400 %, emulated as page zoom with CDP `Emulation.setDeviceMetricsOverride` on a window
  1280 device px wide: 640 CSS px at DPR 2, 320 CSS px at DPR 4. `setPageScaleFactor` is pinch zoom and is not
  used. On every route entry: `innerWidth` 640/320, `devicePixelRatio` 2/4, body text 16 CSS px (32/64 device
  px), horizontal overflow 0.

n14 applies the same zoom emulation to the live page, so the measured state is the one it opened: Home with
items, the add form with Repeat and Previous completion open, item detail, the item edit form, All items with a
search and the Repeat filter applied, the People and things edit form, and Account. While zoomed it asserts that
state is still shown (form open, values kept) and scrolls its own controls into view (Add item/Cancel, Save
changes/Cancel, Save/Cancel, Search and the result link, Edit, Done), then re-checks overflow. Each of these
states, plus Czech All items, also gets a real 320 CSS px viewport with an overflow check, the same control
checks and an axe scan.

### Limits

This is an agent review. No human screen-reader user took part, and ARIA snapshots do not prove what a screen
reader says. The keyboard sweep checks reachability, visible focus and order on route entry. Behaviour inside
forms and dialogs, such as focus after save, cancel, undo, errors and 412 rebase, is covered by n16 and the
Vitest focus tests, not by n21. Focus-indicator contrast is measured only against the surface around the control. Onboarding is checked by n14 (axe, error focus) and the opt-in audit (widths)
because setup has already finished when n21 runs. Zoom is emulated in headless Chromium, not set through the
browser's zoom control. None of this is a WCAG conformance certification.
