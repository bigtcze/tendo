Tendo 2.1 is a quality release. It fixes problems found while testing every part of the app more thoroughly, and it adds no new features. Your data, your settings, and the way items repeat stay the same.

## Fixed in 2.1

- **Saving after a lost connection.** If the connection dropped while you added an item or a person or thing, or marked an item done, **Check again** could sometimes lose track of what you had sent, or send an older attempt again. Tendo now keeps track of the latest attempt for each action, even when the browser cannot save its recovery data.
- **Signing out clears unsent work.** After you signed out, an unfinished add could come back and be sent again when the same account signed in later in that browser tab. Signing out now clears it, even if the browser refuses to remove the saved copy.
- **Leaving a screen during sign-in.** If you left the sign-in, first-run setup, or Account screen while a request was still running, its late answer could still sign you in, move you to the identity provider, or sign you out. Late answers are now ignored once you have left the screen.
- **Undo puts focus back in the right place.** When **Undo** on Home returned an item to a group that was not fully loaded, focus moved to the wrong group. It now moves to the group the item returned to.
- **Long text with emoji.** The search and notes limits counted some characters, such as emoji, twice, so you could not type text the server accepts. Limits in the app now count characters the same way as the server.
- **Sign-in with an identity provider.** When the identity provider could not be reached, Tendo said the sign-in failed. It now says the provider is unavailable, so you can try again later. Starting a sign-in through an address with an explicit default port, such as `https://example.com:443`, no longer fails.
- **Damaged password records.** If a stored password record is damaged, sign-in still says the login or password is incorrect, but the app log now records `password_hash_integrity_fault`, so an administrator can tell the difference. See [troubleshooting](https://github.com/bigtcze/tendo/blob/v2.1.0/docs/admin/troubleshooting.md#sign-in-problems).
- **Stricter address checks.** Requests whose address has a signed port, such as `example.com:+443`, or a non-ASCII host name are now refused instead of being treated as a similar plain address.

## Testing and quality

- Every screen, action, and API endpoint was checked against a written list of features, and missing tests were added, including tests against a real PostgreSQL database and a real browser for complete journeys. This covers repeating and one-off items, dates around daylight-saving changes, undo, invitations, sign-in, sessions, and keeping each household's data separate.
- Lists, search, filters, counts, and paging are tested with more than 1000 items, people, members, invitations, and completions.
- The largest and most tangled parts of the code were split into smaller parts, with tests before and after to show nothing changed. An automatic check now stops code from growing complex again.
- Before each release, an automated run with the Orca screen reader on Linux checks selected headings, navigation, and search controls in English and Czech. No screen-reader user has tested this release, and these checks are not a formal accessibility certification.
- Two people completing the same item at the same moment from two different browsers is tested on the server, but not yet in a real browser.

## Updating from 2.0

Your data is kept, and no new settings are required. 2.1 does not change the database. Back up first ([how](https://github.com/bigtcze/tendo/blob/v2.1.0/docs/admin/backup-restore.md#back-up)), then follow the [update guide](https://github.com/bigtcze/tendo/blob/v2.1.0/docs/admin/update.md#update). If `TENDO_VERSION` in `.env` is `v2` or `latest`, the update steps install 2.1. If it is `v2.0` or `v2.0.0`, change it to `v2.1.0`, `v2.1`, `v2`, or `latest` first.

From 1.x, follow [Updating from 1.x to 2.0](https://github.com/bigtcze/tendo/blob/v2.1.0/docs/admin/update.md#updating-from-1x-to-20); the same steps install 2.1.

## For API clients

`/api/v1` stays compatible: requests that worked with 2.0 return the same results. Two changes are stricter checks on requests that were never valid:

- Address checks now reject signed ports and non-ASCII host names in the effective request host (from `Host` or trusted proxy headers) and in `Origin`.
- `api/openapi.yaml` now states that `password` and `currentPassword` are limited to 512 UTF-8 bytes, which the server already enforced.

## Install

The install steps have not changed. See the [installation guide](https://github.com/bigtcze/tendo/blob/v2.1.0/docs/admin/install.md).

## Not included

- Notifications or reminders outside the app.
- More than one household per account in the interface.
- Password reset. Keep passwords in a password manager.
- TLS. Tendo serves HTTP and expects a reverse proxy in front of it.
- Running under a URL path prefix.

## Assets

- `compose.yaml`: Compose file for PostgreSQL 18 and Tendo.
- `example.env`: settings template. Save it as `.env`.
