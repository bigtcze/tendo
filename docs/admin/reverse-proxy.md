# Reverse proxy boundary

Tendo serves plain HTTP. A reverse proxy terminates TLS and forwards one sanitized hop to the app. These examples use the canonical root origin `https://tendo.test`; replace that hostname consistently with the public host. Tendo supports a domain/subdomain at `/`, not a path prefix. PostgreSQL must stay on a private network and must not publish a host port.

Set `TENDO_PUBLIC_URL` to the exact external origin, including a non-default port when used, with no path other than `/`, query, or fragment. OIDC uses this canonical value to construct its registered callback `<TENDO_PUBLIC_URL>/api/v1/auth/oidc/callback`; never derive the callback from request Host or forwarded headers. The app rejects incorrect scheme/authority with 421 and mismatched `Origin` or unsafe requests without canonical `Origin` with 403. Health endpoints are exempt for HTTP and IP-based probes. A non-health request with the correct public origin proceeds to normal routing (currently an unknown path returns 404).

## Trust boundary

`TENDO_TRUSTED_PROXY_CIDRS` is an optional comma-separated list of CIDRs for the immediate TCP peer, not a list of client networks. Empty means no forwarded headers are trusted. Determine the proxy container's actual address on the app's Docker network and use its exact `/32` (IPv4) or `/128` (IPv6), or a deliberately small dedicated subnet containing only that controlled proxy. Do not assume Docker's bridge subnet or trust broad private ranges; inspect the network and reserve/address it so no other workload can join. Keep the proxy and app on a dedicated network, and prevent untrusted containers from reaching the app network.

All examples match only the configured `tendo.test` DNS hostname. Nginx returns status 421 when the request authority does not match; its default response body is not an app problem document. Traefik returns a router-level 404 for a mismatched host, not the app's RFC 9457 404. Caddy enables the documented global `servers { strict_sni_host }` option, which rejects a TLS SNI/HTTP Host mismatch with 421 before proxying. Caddy's unmatched-host handling can produce an empty 421 response; the smoke test pins TLS SNI to `tendo.test`, sends `Host: attacker.test` to `/not-a-route`, and requires exactly 421 while rejecting the app's JSON 404 (an empty body is valid).

The maintained examples and smoke test cover standard external HTTPS port 443 only; they are not configured for a non-default external port. Proxy host matchers select the DNS hostname and do not include ports. To use another external port, explicitly change the proxy's public listener/port mapping and its forwarded authority so it preserves `hostname:port`, then set `TENDO_PUBLIC_URL=https://hostname:port` to that same exact origin. Ensure the host port is published and reachable by clients; the internal TLS listener can remain on 443. Verify the changed configuration end-to-end before deployment; no alternate-port infrastructure or behavior is implied by these examples.

The proxy must remove every client-supplied `Forwarded` header and overwrite `X-Forwarded-Proto`, `X-Forwarded-Host`, and `X-Forwarded-For` with exactly one known value each. Do not append to client-provided chains or put a second proxy between this sanitizing hop and Tendo. Tendo prefers valid `Forwarded` when present, otherwise requires exactly one proto and host X-Forwarded value; an optional single X-Forwarded-For is accepted. Conflicting formats, duplicates, and chains are rejected. The examples deliberately use X-Forwarded headers only.

## Caddy

Use `deploy/reverse-proxy/Caddyfile`. Mount a certificate/key at `/certs/tendo.test.crt` and `/certs/tendo.test.key`, and attach Caddy to the dedicated app network. The example explicitly removes `Forwarded` and sets the three X-Forwarded values; configure the app's trust CIDR from Caddy's actual network address. Its global default logger excludes `http.log.error`, whose upstream request objects may include query strings; other startup/runtime diagnostics remain enabled. Access logging is not enabled.

## Nginx

Use `deploy/reverse-proxy/nginx.conf` as a full `nginx.conf`; it includes the required top-level `events {}` and `http {}` contexts, including the TLS default server block. Mount the certificate/key at the configured paths and attach Nginx to the dedicated app network. Its `proxy_set_header` directives replace incoming forwarded values. Both access and error logging are directed away (`access_log off;`, `error_log /dev/null;`) because the default error sink can also record request URIs, including query strings, on upstream transport failure. This intentionally trades Nginx diagnostics for query-string privacy; inspect app/container health and temporarily enable carefully sanitized Nginx diagnostics only when needed.

## Traefik

Use `deploy/reverse-proxy/traefik.yml` and `deploy/reverse-proxy/traefik-dynamic.yml` with the file provider. Mount the certificate and configure the Traefik TLS certificate in your deployment; the dynamic example defines the HTTPS router and service. Attach Traefik to the dedicated app network and set its actual peer CIDR in the app configuration. `customRequestHeaders` clears `Forwarded` and replaces the forwarded proto/host values. This example deliberately omits optional client-IP forwarding; Tendo does not need it for the documented origin checks.

## Verification

The proxy smoke test uses Docker Compose, Docker Engine, curl, OpenSSL, and Python 3. From the repository root, run `bash scripts/proxy-smoke.sh`; it independently tests all three maintained images: Caddy `2.11.4-alpine`, Nginx `1.30.3-alpine`, and Traefik `v3.7.7`. To debug one proxy, use `PROXY=caddy bash scripts/proxy-smoke.sh` (also `nginx` or `traefik`). Each run builds the production app, starts real PostgreSQL, and issues verified HTTPS requests using the generated local CA with `curl --cacert` and hostname resolution; TLS verification is never disabled.

The isolated test reserves `172.29.247.10/32` for the proxy and `.20` for Tendo, with an untrusted test peer at `.30`; it sends canonical `Host: tendo.test` and configures only the proxy address as trusted. It checks mismatched TLS SNI/Host status (Nginx 421; Traefik router-level 404 distinct from the app's JSON problem response; Caddy strict SNI/Host rejection with exactly 421, allowing an empty body but rejecting the app's JSON 404), normal-path and app-stopped transport-failure requests (Caddy/Traefik 502; Nginx upstream timeout (HTTP 504) containing synthetic query secrets while asserting those secrets are absent from proxy container logs, forwarded-header sanitization including a proxy-stripped malformed forwarded-value 400, origin/status behavior, problem details and headers, request-ID propagation, readiness returning 503 while PostgreSQL is stopped, and readiness returning 200 after recovery. It does not check liveness while PostgreSQL is stopped; liveness checks occur with the database running. PostgreSQL has no published host port. The smoke test mounts these same configuration files, certificates, and paths, so they are directly exercised rather than reconstructed separately.

The current runtime includes health endpoints, browser first-run onboarding protected by an operator setup code, local login sessions, an empty home screen, and a "People and things" screen. OIDC linking and login are available through the API when configured, but OIDC browser buttons are not included in this release; items and invitations remain API-only. Household access is a read-only, membership-checked `GET /api/v1/households/{householdId}` plus the household-scoped subjects API under `/api/v1/households/{householdId}/subjects`. The session cookie follows `TENDO_PUBLIC_URL`: with an `https://` public URL it is named `__Host-tendo_session` and marked `Secure` even though the app itself listens on plain HTTP; the proxy must not rewrite or drop `Set-Cookie`. The smoke test checks this through Caddy, Nginx, and Traefik. Do not treat it as a usable household installation; TLS and a proxy do not add those product features. First-run setup requires the canonical Origin and the operator-generated `TENDO_SETUP_TOKEN` (the "setup code" in the browser); it is not public visitor registration.
